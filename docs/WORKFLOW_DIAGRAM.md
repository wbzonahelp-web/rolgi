# Git Workflow - Визуальная схема

## Основной процесс разработки

```
                    MAIN BRANCH (protected)
                         │
                         │  git checkout -b feature/new-feature
                         ├──────────────────────────────────────►
                         │                                      │
                         │                            FEATURE BRANCH
                         │                                      │
                         │                              ┌───────┴───────┐
                         │                              │  Разработка   │
                         │                              │  + Коммиты    │
                         │                              └───────┬───────┘
                         │                                      │
                         │  git fetch origin main               │
                         │◄─────────────────────────────────────┤
                         │                                      │
                         │  git rebase origin/main              │
                         ├─────────────────────────────────────►│
                         │                              ┌───────┴───────┐
                         │                              │ Синхронизация │
                         │                              │   + Rebase    │
                         │                              └───────┬───────┘
                         │                                      │
                         │                              ┌───────┴───────┐
                         │                              │     Squash    │
                         │                              │   коммитов    │
                         │                              └───────┬───────┘
                         │                                      │
                         │  git push -f origin feature          │
                         │◄─────────────────────────────────────┤
                         │                                      │
                         │                              ┌───────┴───────┐
                         │                              │  Pull Request │
                         │◄─────────────────────────────┤   на GitHub   │
                         │                              └───────────────┘
                    ┌────┴────┐
                    │  Merge  │
                    │   PR    │
                    └─────────┘
```

## Детальная схема коммитов

### До Squash
```
Feature Branch:  A─B─C─D─E     (5 коммитов)
                 │
Main Branch:     M
```

### После Squash
```
Feature Branch:  A'            (1 коммит = A+B+C+D+E)
                 │
Main Branch:     M
```

### После Merge PR
```
Main Branch:     M─────A'      (чистая история)
```

## Workflow с конфликтами

```
┌──────────────────────────────────────────────────────────────┐
│  1. FETCH: Получить изменения из main                       │
├──────────────────────────────────────────────────────────────┤
│  $ git fetch origin main                                     │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  2. REBASE: Применить изменения поверх main                 │
├──────────────────────────────────────────────────────────────┤
│  $ git rebase origin/main                                    │
└──────────────────────────────────────────────────────────────┘
                            ↓
                    ╔═══════════════╗
                    ║  Конфликты?   ║
                    ╚═══════════════╝
                      ↙           ↘
                 ДА                    НЕТ
                  ↓                     ↓
    ┌────────────────────────┐    ┌──────────────────┐
    │  3a. Разрешить         │    │  4. Продолжить   │
    │  конфликты вручную     │    │  с push          │
    ├────────────────────────┤    └──────────────────┘
    │  • git status          │
    │  • Отредактировать     │
    │  • git add <files>     │
    │  • git rebase          │
    │    --continue          │
    └────────────┬───────────┘
                 ↓
    ┌────────────────────────┐
    │  3b. Приоритет:        │
    │  КОД ИЗ MAIN           │
    └────────────┬───────────┘
                 ↓
            [Продолжить]
```

## Conventional Commits - Структура

```
┌─────────────────────────────────────────────────────────┐
│  type(scope): subject                                   │
│                                                          │
│  body (опционально)                                     │
│                                                          │
│  footer (опционально)                                   │
└─────────────────────────────────────────────────────────┘
     │      │        │
     │      │        └─► Краткое описание (до 50 символов)
     │      │
     │      └──────────► Область изменений (опционально)
     │
     └─────────────────► Тип изменений (обязательно)
```

### Типы коммитов

```
feat     ──► 🎨  Новая функциональность
fix      ──► 🐛  Исправление бага
docs     ──► 📚  Документация
style    ──► 💄  Форматирование кода
refactor ──► ♻️  Рефакторинг
test     ──► ✅  Тесты
chore    ──► 🔧  Обслуживание/конфигурация
```

## Branch Naming Convention

```
┌────────────────────────────────────────────────────┐
│  type/description-in-kebab-case                    │
└────────────────────────────────────────────────────┘
   │           │
   │           └─► Описание через дефис
   │
   └─────────────► Тип ветки

Примеры:
├─ feature/user-authentication
├─ feature/payment-integration
├─ bugfix/login-timeout
├─ bugfix/null-pointer-fix
├─ hotfix/critical-security-patch
└─ docs/api-documentation
```

## Pull Request Lifecycle

```
1. CREATE BRANCH          ┌──────────────────┐
   ┌──────────────┐       │   Git History    │
   │ main → feature│       │                  │
   └──────┬───────┘       │  main:    M      │
          │               │  feature: M─A    │
          ↓               └──────────────────┘

2. DEVELOP & COMMIT       ┌──────────────────┐
   ┌──────────────┐       │   Git History    │
   │ Work + commits│       │                  │
   └──────┬───────┘       │  main:    M      │
          │               │  feature: M─A─B─C│
          ↓               └──────────────────┘

3. SYNC WITH MAIN         ┌──────────────────┐
   ┌──────────────┐       │   Git History    │
   │ fetch + rebase│       │                  │
   └──────┬───────┘       │  main:    M─X─Y  │
          │               │  feature: M─X─Y─A'│
          ↓               └──────────────────┘

4. SQUASH COMMITS         ┌──────────────────┐
   ┌──────────────┐       │   Git History    │
   │ reset + commit│       │                  │
   └──────┬───────┘       │  main:    M─X─Y  │
          │               │  feature: M─X─Y─Z│
          ↓               └──────────────────┘

5. PUSH & CREATE PR       ┌──────────────────┐
   ┌──────────────┐       │   GitHub         │
   │ push -f + PR  │       │                  │
   └──────┬───────┘       │  PR: feature → main
          │               │  Status: Open    │
          ↓               └──────────────────┘

6. REVIEW & MERGE         ┌──────────────────┐
   ┌──────────────┐       │   Git History    │
   │ Approval + merge      │                  │
   └──────┬───────┘       │  main: M─X─Y─Z   │
          │               │  feature: deleted │
          ↓               └──────────────────┘
   [COMPLETE]
```

```

║                  ОСНОВНЫЕ КОМАНДЫ                        ║
╠══════════════════════════════════════════════════════════╣

║  Синхронизация    │  git fetch origin main              ║
║  Rebase           │  git rebase origin/main             ║
║  Squash           │  git reset --soft HEAD~N            ║
║  Push             │  git push -f origin feature/name    ║
║  Статус           │  git status                         ║
║  История          │  git log --oneline --graph          ║
╚══════════════════════════════════════════════════════════╝
```

## Правила и Best Practices

```
✅ DO (ДЕЛАТЬ):
├─ Коммитить после каждого изменения
├─ Использовать conventional commits
├─ Синхронизироваться с main перед PR
├─ Объединять коммиты (squash) перед PR
├─ Писать осмысленные сообщения
├─ Разрешать конфликты (приоритет: main)
└─ Создавать PR для всех изменений

❌ DON'T (НЕ ДЕЛАТЬ):
├─ Пушить напрямую в main
├─ Оставлять незакоммиченные изменения
├─ Создавать PR без синхронизации
├─ Использовать "fix", "update" как сообщение
└─ Оставлять множество мелких коммитов в PR
```

```
                            │
                           ДА
                            ↓

                   │  Есть ветка     │

                   └────────┬────────┘
                      ↙            ↘
                    НЕТ            ДА
                     ↓              ↓
         ┌──────────────────┐    ┌──────────────────┐
         │ Создать ветку    │    │ Переключиться    │
         │ git checkout -b  │    │ git checkout     │
         └──────┬───────────┘    └──────┬───────────┘
                │                       │
                └───────────┬───────────┘
                            ↓
                   ┌─────────────────┐
                   │  Внести         │
                   │  изменения      │
                   └────────┬────────┘
                            ↓
                   ┌─────────────────┐
                   │  git add .      │
                   │  git commit     │
                   └────────┬────────┘
                            ↓
                   ┌─────────────────┐
                   │  Еще изменения? │
                   └────────┬────────┘
                      ↙            ↘
                    ДА            НЕТ
                     ↓              ↓
                [Повторить]    ┌──────────────────┐
                               │  git fetch       │
                               │  git rebase      │
                               └──────┬───────────┘
                                      ↓
                               ┌──────────────────┐
                               │  git reset       │
                               │  (squash)        │
                               └──────┬───────────┘
                                      ↓
                               ┌──────────────────┐
                               │  git push -f     │
                               └──────┬───────────┘
                                      ↓
                               ┌──────────────────┐
                               │  Создать PR      │
                               │  на GitHub       │
                               └──────────────────┘
```
