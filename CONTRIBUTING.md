# Руководство по внесению вклада

## Pull Request Process

### 1. Подготовка к работе

Перед началом работы убедитесь, что:
- У вас настроен Git: `git config user.name` и `git config user.email`
- У вас есть доступ к репозиторию
- Вы синхронизировали свою локальную копию с удаленным репозиторием

### 2. Создание ветки

Создайте новую ветку от `main`:

```bash
git checkout main
git pull origin main
git checkout -b feature/описание-функции
```

### 3. Разработка

- Делайте атомарные коммиты (один коммит = одна логическая единица изменений)
- Используйте conventional commits формат
- Коммитьте часто (после каждого значимого изменения)

```bash
# После изменений
git add .
git commit -m "feat(module): add new functionality"
```

### 4. Синхронизация перед PR

**ОБЯЗАТЕЛЬНО перед созданием/обновлением PR:**

```bash
# Получить последние изменения из main
git fetch origin main

# Применить изменения поверх текущих
git rebase origin/main

# Если есть конфликты - разрешить их
# 1. Посмотреть конфликтные файлы
git status

# 2. Отредактировать файлы (приоритет - код из main)
# 3. Добавить разрешенные файлы
git add <файлы>

# 4. Продолжить rebase
git rebase --continue
```

### 5. Объединение коммитов (Squashing)

Перед созданием PR объедините все свои коммиты в один:

```bash
# Если у вас 5 коммитов, которые нужно объединить
git reset --soft HEAD~5

# Создать один комплексный коммит
git commit -m "feat(module): comprehensive description of all changes

- Added feature X
- Fixed issue Y
- Updated documentation Z"
```

### 6. Отправка изменений

```bash
# Первая отправка
git push origin feature/описание-функции

# После rebase/squash (требуется force push)
git push -f origin feature/описание-функции
```

### 7. Создание Pull Request

1. Перейдите на GitHub: https://github.com/wbzonahelp-web/rolgi
2. Нажмите "New Pull Request"
3. Выберите вашу ветку -> main
4. Заполните шаблон PR:

```markdown
## Описание
Краткое описание изменений

## Тип изменений
- [ ] Новая функциональность (feat)
- [ ] Исправление бага (fix)
- [ ] Документация (docs)
- [ ] Рефакторинг (refactor)
- [ ] Тесты (test)

## Как протестировано
- [ ] Локальные тесты пройдены
- [ ] Ручное тестирование выполнено

## Чеклист
- [ ] Код следует стандартам проекта
- [ ] Коммиты объединены в один
- [ ] Синхронизация с main выполнена
- [ ] Конфликты разрешены
- [ ] Документация обновлена (если нужно)
```

5. Создайте PR и поделитесь ссылкой

### 8. Code Review

- Ответьте на комментарии ревьюеров
- Внесите необходимые изменения
- После approval PR будет смержен в main

## Правила разрешения конфликтов

1. **Приоритет remote кода**: При конфликтах сохраняйте логику из main, если ваши изменения не критичны
2. **Тестирование**: После разрешения конфликтов обязательно протестируйте код
3. **Документирование**: Опишите решения в commit message, если конфликт был значительным
